Implementations / Patch management

Patch management

Keeping operating systems and software up to date in a controlled, tested way.

What it is

Software vendors constantly release updates that fix security holes and bugs. Many successful attacks exploit vulnerabilities that already had a fix available; the patch simply hadn't been installed.

Patch management makes updating systematic. Know what's installed, know what's missing, test updates so they don't break anything, roll them out on a schedule and confirm they actually landed.

The cycle

  1. InventoryKnow every system and what software and versions it runs.
  2. IdentifyCompare against vendor releases to see which patches are missing.
  3. TestInstall updates on a small pilot group first to catch problems.
  4. DeployRoll out to everything else during planned maintenance windows.
  5. VerifyConfirm installs succeeded and document any exceptions.

In practice

What it looks like in a real environment

Typical scenarios from organizations across the industry.

Example

Patch Tuesday

Microsoft releases security updates on the second Tuesday of each month. Many IT teams test them on a pilot group that week, then roll them out to everyone over the following week or two.

Example

An emergency fix

A flaw that attackers are already exploiting gets an out-of-band patch. The team skips the normal schedule and patches exposed systems the same day.

Example

A system that can't be updated

An old machine runs software that breaks on newer updates. It's documented as an exception and protected with compensating controls, like network isolation, until it can be replaced.

Toolbox

Common tools in the industry

  • Microsoft Intune
  • Microsoft Configuration Manager
  • WSUS
  • PDQ Deploy
  • Ansible

Examples of widely used options, not an endorsement, and not necessarily what our lab runs.

Key terms

Patch Tuesday
Microsoft's regular monthly release of security updates.
Pilot group
A small set of systems that get updates first to catch problems.
Maintenance window
A scheduled time when changes and reboots are allowed.
Compensating control
An alternative safeguard used when the normal fix isn't possible.
